# LAN starter session

This fork prototype is separate from sharing arbitrary projects and media. Two
participants construct the same deterministic, self-authored MIDI starter locally. The host
owns the canonical controls; each app renders its own copy with independent play/stop/seek.
The only shared edits are track name, volume and pan on four fixed tracks. Clips, devices,
files, recording, project snapshots and plugins are not remote inputs.

## Invitation and connection

Starting is explicit. The host binds one user-selected private or loopback IPv4 address and
an ephemeral port. No listener exists before this action; no discovery, public relay or account
is used. The UI can suggest the route's private local address without sending a UDP datagram.
Public IPv4 addresses and DNS targets are refused for this milestone.

The invitation contains protocol 1, address, the host's self-signed TLS certificate and a
256-bit OS-random admission secret. It is copyable but never logged or persisted. Its Debug
representation is redacted. The invitation expires after five minutes and is redeemed once.
Stopping or replacing the host revokes it. One guest is admitted at a time. An old invitation
does not resume a disconnected peer; create a fresh host session to invite again.

TLS 1.3 uses rustls and a certificate generated by rcgen for suhina.local. The guest trusts
only the certificate in the invitation, verifies that name and normal handshake signatures,
then proves possession of the secret inside TLS. No insecure certificate verifier is used.
The stored secret hash is compared in constant time. Neither a valid TCP connection nor a
numeric local peer handle authorizes an edit. Authentication failure reports no secret.

## Bounded exchange

Messages are UTF-8 JSON prefixed by an unsigned 32-bit big-endian byte length, maximum 8192
bytes checked before allocating the body. Empty, oversized, truncated, invalid-version and
unknown/duplicate-field envelopes are refused. Strings, track sets and numeric values have
independent bounds. No filesystem path, serialized model or plugin state is accepted.

An authenticated guest sends a poll or one edit with its sequence and base revision. The
host maps it to its own authenticated PeerId, then uses the existing collaboration Host and
Edit allowlist. The reply is a complete bounded control snapshot and acceptance/rejection.
Stale edits are rejected visibly; the client does not silently rebase or retry them. Accepted
sequence numbers advance only after host acceptance. Connections poll at a bounded rate and
have read/write/handshake deadlines. Pending connections, UI edit queues and peers are capped.

Control snapshots may skip revisions because they contain all four tracks. A client validates
all fields before applying any, rejects backwards revisions, and applies only changed controls
through the session command path. A reused revision with different controls is an error.
Local transport never enters the wire or increments the shared revision. Disconnect preserves
the last local project and stops sharing; it does not discard the person's project or audio.

## Desktop boundary

The app opens a new dedicated starter tab, preserving existing projects. While shared, that
tab's mutation gate accepts authoritative control updates through a host-owned API, and normal
commands cannot edit its clips, instruments or history. Private play/stop/seek remain available.
This gate also applies to attached agents, not just disabled UI buttons. Other tabs stay local.
Leaving unlocks the retained starter project for normal solo editing. Network actions are not
offered to MCP agents. All networking and canonical-host work run away from the audio thread.

## Validation and limits

Automated tests cover real encrypted loopback host/guest traffic, certificate mismatch,
wrong/reused/expired invitations, invalid frames and protocol versions, stale/duplicate edits,
stop/disconnect, an incomplete-handshake deadline and private transport independence. UI tests cover the
entry point and preservation of other projects. A loopback test is not evidence of successful
firewall traversal or a physical Mac-to-Windows session; document those separately.

The first desktop slice provides a starter-session control experiment, not full music project
coediting. Arbitrary project/media exchange still depends on the portable-asset work. Shared
note editing, recording publication, linked transport, internet connectivity, reconnect/resume,
presence cursors and host migration remain later milestones.
